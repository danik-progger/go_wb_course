# 📦 Демонстрационный сервис заказов (L0)

Этот проект представляет собой демонстрационный микросервисный комплекс для обработки и отображения данных о заказах. Система получает данные из очереди сообщений **Kafka**, сохраняет их в базу данных **PostgreSQL**, кэширует в памяти и предоставляет доступ к ним через **HTTP API** с простым веб-интерфейсом.

---

## 🛠️ Технологии

- **Backend**: Go 🐹
- **Frontend**: SvelteKit ✨
- **База данных**: PostgreSQL 🐘
- **Брокер сообщений**: Kafka 📬
- **Оркестрация**: Docker & Docker Compose 🐳

---

## 🏗️ Структура проекта

Проект разделен на несколько независимых сервисов, каждый из которых выполняет свою задачу:

- **📤 `producer`**: Симулятор, который читает данные о заказах из `JSON`-файлов и отправляет их в топик Kafka.
- **📥 `consumer`**: Сервис, который подписывается на топик Kafka, получает сообщения, валидирует их и сохраняет в базу данных PostgreSQL.
- **⚙️ `back`**: Основной бэкенд-сервис, который предоставляет HTTP API. При старте он восстанавливает свой кэш из базы данных. Запросы на получение заказа обслуживаются из кэша для максимальной производительности.
- **🖥️ `front`**: Простое веб-приложение на SvelteKit, которое позволяет пользователю ввести `ID` заказа и получить по нему информацию, обращаясь к API сервиса `back`.
- **🗄️ `db`**: Экземпляр PostgreSQL, развернутый в Docker-контейнере.
- **📬 `kafka`**: Экземпляр Apache Kafka, используемый как брокер сообщений.

## 🚀 Запуск проекта

1️⃣ **Установка Docker**: Убедитесь, что на вашей машине установлены `Docker` и `Docker Compose`.

2️⃣ **Переменные окружения**: Создайте файл `.env` в корневой директории `l0/` и определите в нем необходимые переменные (можно скопировать из `.env.example`, если он есть, или использовать значения по умолчанию из `docker-compose.yml`).

3️⃣ **Сборка и запуск**: Выполните команду в директории `l0/`:
   ```bash
   docker-compose up --build
   ```
   Эта команда соберет образы для всех сервисов и запустит их.

4️⃣ **Проверка**:
   - `producer` автоматически отправит несколько тестовых заказов.
   - ✅ Веб-интерфейс будет доступен по адресу: `http://localhost:5173`.
   - ✅ Бэкенд-сервис будет доступен по адресу: `http://localhost:8081`.

## 📡 API

Сервис `back` предоставляет следующий эндпоинт:

- **Метод**: `GET`
- **URL**: `/order/:order_uid`
- **Описание**: Возвращает полную информацию о заказе по его уникальному идентификатору.
- **Пример запроса**:
  ```bash
  curl http://localhost:8081/order/b563feb7b2b84b6test
  ```
- **Ответ**:
  - 🟢 `200 OK`: В случае успеха возвращает `JSON`-объект с данными заказа.
  - 🔴 `404 Not Found`: Если заказ с таким `ID` не найден.

## ✨ Ключевые особенности реализации

- **⚡️ Кэширование**: При старте сервис `back` загружает все существующие заказы из PostgreSQL в локальный кэш (in-memory `map`). Все запросы к API обслуживаются напрямую из кэша, что обеспечивает минимальную задержку.

- **🛠️ Обработка данных**: Сервис `consumer` отвечает за обработку входящих сообщений. Он производит валидацию данных. Невалидные сообщения игнорируются и логируются. Валидные данные сохраняются в PostgreSQL с использованием транзакций для обеспечения целостности данных.

- **💪 Отказоустойчивость**:
  - **Брокер сообщений**: Использование Kafka гарантирует, что сообщения не будут потеряны, даже если сервис `consumer` временно недоступен.
  - **Восстановление кэша**: При перезапуске `back`-сервиса кэш полностью восстанавливается из базы данных, что позволяет избежать потерь данных и продолжить обслуживание запросов без задержек.
  - **Транзакции БД**: Сохранение данных в базу происходит в рамках транзакций, что предотвращает частичную запись данных в случае ошибок.
